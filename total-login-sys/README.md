# 통합로그인 (TotalLoginSys)

여러 웹사이트의 계정을 안전하게 보관하고, 목록에서 사이트를 누르면 **자동으로 로그인된 창**을 열어 주는 모바일 앱입니다.
React Native(Expo) + TypeScript로 만들었고 Android / iOS 모두 지원합니다.

## 주요 기능

| 기능 | 설명 |
|---|---|
| 최초 설정 | 처음 실행하면 관리자 아이디/비밀번호를 설정 (재설치하면 다시 설정) |
| 앱 로그인 | 아이디/비밀번호, **지문 인식**, **얼굴 인식** 중 선택. 최초 설정 직후 지문 로그인을 바로 켤 수 있음 |
| 로그인 유지 | 다른 앱에 다녀와도 설정한 시간(즉시/1/5/30분, 기본 5분) 안이면 로그인 유지 |
| 백업 / 복원 | 사이트 목록을 백업 비밀번호로 암호화한 `.tlsbackup` 파일로 내보내기(드라이브·메신저 등) / 가져오기 |
| 웹사이트 관리 | 사이트 추가 / 편집 / 삭제 / 검색 |
| 자동 로그인 | 사이트를 누르면 앱 안의 창에서 열리며 아이디/비밀번호를 자동 입력하고 로그인 |
| 2단계 로그인 대응 | "아이디 입력 → 다음 → 비밀번호" 형태의 로그인 화면도 대응 |
| 고급 설정 | 입력창을 자동으로 못 찾는 사이트는 CSS 선택자를 직접 지정 |
| http 사이트 | 사이트별로 "안전하지 않은(http) 사이트 허용"을 켜면 http 주소도 열고 자동 로그인 |

## 보안 설계

- **관리자 비밀번호**: 평문으로 저장하지 않음. PBKDF2-SHA256(10만 회) + 랜덤 솔트로 해시, 비교는 상수 시간 비교
- **사이트 계정 정보**: 전체 목록을 AES-256-GCM으로 암호화해 저장. 암호화 키는 iOS Keychain / Android Keystore에만 보관 ("이 기기에서만, 잠금 해제 상태에서만" 접근 가능)
- **변조 탐지**: GCM 인증 태그로 저장 데이터가 바뀌면 복호화를 거부
- **무차별 대입 방지**: 5회 실패 시 30초 잠금, 이후 실패마다 2배(최대 1시간). 앱을 재시작해도 유지
- **생체인증**: 성공 여부(true/false)만 믿지 않고, 생체인증을 통과해야만 꺼낼 수 있는 보안 토큰으로 검증. 기기에 **지문/얼굴이 새로 등록되면 자동으로 무효화**되어 비밀번호 로그인을 요구. 기기 PIN으로의 우회는 막음. Android에서는 사진으로 뚫릴 수 있는 약한 등급(Class 2) 얼굴인식은 허용하지 않음
- **피싱 방지 자동입력**: 계정 정보는 페이지 로드 후 현재 주소가 **등록한 도메인과 정확히 일치하는 https 페이지**일 때만 입력. 다른 도메인으로 리다이렉트되면 입력하지 않음. 문자열은 JSON으로 이스케이프해 스크립트 인젝션 불가
- **웹 창 제한**: https 외 이동(http, javascript:, intent:, file: 등) 차단 — 단, 사용자가 경고를 확인하고 "http 허용"을 켠 사이트에서만 http 이동·자동 입력 허용(그 사이트의 도메인 일치 검사는 그대로), 혼합 콘텐츠 차단, 파일 접근 차단, 팝업 창 차단, 폼 데이터 저장 안 함
- **자동 잠금**: 다른 앱으로 전환 후 유지 시간(기본 5분)이 지나 돌아오면 잠그고 메모리의 계정 목록을 폐기. 일정 시간(3/10/30분, 기본 10분) 조작이 없어도 잠금 — 웹사이트 창 안의 조작도 활동으로 인정. 앱이 직접 띄운 파일 선택·공유·생체인증 창은 전환으로 보지 않음
- **화면 보호**: 화면 캡처·녹화 차단(Android), 최근 앱 목록에서 화면 가림
- **백업 차단**: Android 클라우드 백업 비활성화 (`allowBackup: false`). 데이터는 외부 서버로 전송되지 않음
- **수동 백업 파일**: 관리자 비밀번호 재확인 후에만 내보내기. PBKDF2-SHA256(10만 회) + 랜덤 솔트로 백업 비밀번호에서 키를 만들고 AES-256-GCM으로 암호화(기기 키와 무관 → 새 폰에서 복원 가능). 평문 파일은 만들지 않고, 공유용 임시 파일은 공유 직후 삭제
- **재설치 감지**: iOS는 앱을 지워도 Keychain이 남기 때문에, 재설치를 감지하면 이전 데이터를 모두 삭제
- 중요한 설정 변경(로그인 방식, 초기화) 시 관리자 비밀번호 재확인

## 개발 환경 (VSCode)

1. [Node.js LTS](https://nodejs.org) 설치
2. VSCode로 이 폴더 열기 → 우측 하단 "권장 확장 설치" 클릭 (Expo Tools, ESLint, Prettier 등)
3. 터미널(`Ctrl + ` `)에서:

```bash
npm install
```

## 실행 방법

> 지문/얼굴 인식, 보안 저장소 같은 네이티브 기능을 쓰므로 **Expo Go 앱이 아니라 개발 빌드(development build)** 로 실행해야 합니다.
> (특히 iOS Face ID는 Expo Go에서 동작하지 않습니다.)

### Android (Windows에서 가능)

1. [Android Studio](https://developer.android.com/studio) 설치 → SDK 설치
2. 폰에서 개발자 옵션 → USB 디버깅 켜고 PC에 연결 (또는 에뮬레이터 실행)
3. 실행:

```bash
npx expo run:android
```

### iOS

Mac + Xcode가 필요합니다. Mac이 없다면 EAS 클라우드 빌드를 사용하세요.

```bash
npx eas-cli@latest build --profile development --platform ios
```

### 설치 파일(APK/AAB) 만들기

```bash
npx eas-cli@latest build --platform android
```

    LoginScreen.tsx             앱 로그인
    SiteListScreen.tsx          웹사이트 관리(목록)
    SiteEditScreen.tsx          사이트 추가/편집
    SiteBrowserScreen.tsx       자동 로그인 웹 창

  components/                   공통 UI, 비밀번호 재확인 창, 백업 비밀번호 창

## 사용 팁 / 한계

- **로그인 주소**는 로그인 입력창이 있는 페이지의 *실제* 주소를 넣으세요. 예: 네이버는 `naver.com`이 아니라 `https://nid.naver.com/nidlogin.login`. 계정 정보는 이 주소의 도메인에서만 입력됩니다.
- 캡차(자동입력 방지 문자), 휴대폰 인증, OTP 등 **2차 인증이 있는 사이트는 그 단계를 사용자가 직접** 진행해야 합니다.
- 일부 사이트(은행 등)는 보안 키패드나 자동입력 차단 기술을 써서 자동 로그인이 되지 않을 수 있습니다.
- 관리자 비밀번호를 잊으면 복구할 수 없습니다. 설정 > 전체 초기화 후 다시 등록해야 합니다(보안상 의도된 동작).
- 폰을 바꾸기 전에 **설정 > 백업 내보내기**로 백업 파일을 만들어 두세요. 백업 비밀번호를 잊으면 백업 파일도 열 수 없습니다.
- Android 얼굴 인식은 기기가 "강한 등급(Class 3)" 얼굴인식을 지원해야 사용할 수 있습니다. 대부분의 Android 폰은 지문을 권장합니다.
